# 教小机装衣柜

这份教程写给帮人安装衣柜的小机。网页和 MCP 共用一份数据；先读配置，再用实际 id。下面的 `human` / `ai` 和六个分类 id 只是出厂示例。

## 我家小机能用吗

能接 MCP 就能用：支持本地进程就接 stdio，支持远程服务就接 Streamable HTTP。能往聊天塞消息，就用两个 webhook 给小机递便签；塞不了，就让小机自己翻未读。选择接法看客户端能力，不依赖某个前端名称。

给使用者一段可粘进项目说明 / 自定义指令的话：

> 每次对话开头，或我说“抽好了”“挑好了”时，先调用 wardrobe_unread，查看我给自己和给你抽挑的未读记录。读完文字与附言，需要看图时调用 wardrobe_view 或 wardrobe_card，再用 wardrobe_mark_read 标记实际看过的记录。remaining 大于 0 时继续查。不要为检查未读而重新抽卡；我找入口时，用 wardrobe_link 给我“打开衣柜”链接。

## 1. 安装与启动

进入拿到的 `our-wardrobe` 项目目录：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-mcp.txt
cp config.json config.local.json
export WARDROBE_API_KEY="$(python -c 'import secrets; print(secrets.token_urlsafe(32))')"
export WARDROBE_URL="http://127.0.0.1:8765"
python -m wardrobe
```

保管好密钥，网页、HTTP API 与 stdio MCP 都用这个值；远程 MCP 另配独立密钥，不要放进仓库或交接报告。服务终端保持运行，另开终端执行 `curl --fail http://127.0.0.1:8765/health`，应得到 `{"status":"ok"}`。浏览器打开同一地址，输入密钥即可进入衣柜。

服务默认空柜。可以在网页点“放进柜子”，也可以用 MCP 添加。可选 `python scripts/seed.py` 导入五件虚构无图衣物；新终端需要激活相同虚拟环境、设置相同密钥。

## 2. 配置名字和分类

`config.local.json` 默认有 `human`（我）和 `ai`（小机），可以修改显示名。若改 id，首次添加数据前同步改 `clients`、分类 `owners` 和 `in_outfit` 数组。配置改后重启服务。

人有六格：衣服、袜子、饰品、玩具、药品、指令；小机没有袜子格。人的默认套装是前四格，小机的默认套装是其全部五格。玩具默认可抽 1–3 件，其余每格 1 件。删掉不需要的分类即可，也能自行增加；详细字段见 README。

先保持 `webhook_url` 和 `notify_webhook_url` 为空。基本流程跑通后再接自己的聊天入口。

## 3. 注册 stdio MCP

HTTP 服务必须单独运行；MCP 进程只负责连接它。取得 Python 和脚本绝对路径：

```bash
python -c 'import sys; from pathlib import Path; print(sys.executable); print(Path("wardrobe_mcp.py").resolve())'
```

在支持 stdio MCP 的客户端增加一个服务器，命令用第一行 Python 路径，参数用第二行脚本路径，环境变量设置 `WARDROBE_URL`、`WARDROBE_API_KEY`。例如客户端使用 `mcpServers` 配置时：

```json
{
  "mcpServers": {
    "wardrobe": {
      "command": "/absolute/path/our-wardrobe/.venv/bin/python",
      "args": ["/absolute/path/our-wardrobe/wardrobe_mcp.py"],
      "env": {
        "WARDROBE_URL": "http://127.0.0.1:8765",
        "WARDROBE_API_KEY": "填写自己保存的服务密钥"
      }
    }
  }
}
```

保留客户端已有服务器配置，只添加这个条目；不要把含密钥的配置提交。项目已忽略 `.mcp.json`。客户端若支持环境变量引用，也可以按它的规则引用密钥。远端 MCP 的 `127.0.0.1` 指它自己，跨机器时填写能访问的服务地址。

## 3.1 只接受公网地址时：远程 MCP

服务环境保留 WARDROBE_API_KEY，另设：

```bash
export WARDROBE_MCP_KEY="$(python -c 'import secrets; print(secrets.token_urlsafe(32))')"
export PUBLIC_URL="https://wardrobe.example.org"
python -m wardrobe --host 127.0.0.1 --port 8765
```

保存两个不同的密钥，后续重启复用。服务挂载 Streamable HTTP `/mcp/<WARDROBE_MCP_KEY的值>`，同样有全部 16 个工具。不设置 WARDROBE_MCP_KEY 就关闭公网 MCP。

选择一种 HTTPS 部署方式，域名替换为自己的：

**Caddy**：DNS 指向服务器，开放 80/443，在 Caddyfile 写入：

```caddyfile
wardrobe.example.org {
    reverse_proxy 127.0.0.1:8765
}
```

**Cloudflare Tunnel**：已有 Cloudflare 域名并安装 cloudflared 后：

```bash
cloudflared tunnel login
cloudflared tunnel create wardrobe
cloudflared tunnel route dns wardrobe wardrobe.example.org
```

本机 `tunnel.yml`（替换 UUID 和凭据文件路径）：

```yaml
tunnel: YOUR-TUNNEL-UUID
credentials-file: /absolute/path/YOUR-TUNNEL-UUID.json
ingress:
  - hostname: wardrobe.example.org
    service: http://127.0.0.1:8765
  - service: http_status:404
```

执行 `cloudflared tunnel --config tunnel.yml run wardrobe`。公网是 HTTPS，本机服务仍为 HTTP；两种部署都保留完整 `/mcp/...` 路径，不加交互登录页或验证码。配置参考 [Caddy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy)、[Cloudflare Tunnel](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/local-management/create-local-tunnel/)。

在 claude.ai 设置 → Connectors 中添加自定义连接器，填写 `https://wardrobe.example.org/mcp/<实际密钥>`；可选 OAuth 字段留空。对话中启用后，先调用 wardrobe_config、wardrobe_link 验证。官方 App 使用同一账号的连接器，入口以实际界面为准。连接从云端发起，必须是公网 HTTPS 443，不能填 localhost。[官方操作说明](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp)

**完整 MCP 地址即凭据**：不要发送到聊天、截图或报告；不要放进 PUBLIC_URL、卡片、嵌入按钮。浏览器历史、代理/CDN日志和诊断可能记录路径，需关闭或脱敏请求路径日志并限制访问。内置启动器已关闭 Uvicorn 访问日志；自行启动 uvicorn 时加 `--no-access-log`。泄露后换 WARDROBE_MCP_KEY、重启服务并更新连接器，旧地址失效，网页密钥不变。

## 3.2 给人留下入口

`wardrobe_link()` 返回 PUBLIC_URL 的“打开衣柜”链接，发给人即可；打开后输入网页密钥。每次新卡片页脚和 webhook 的 text / wardrobe_url 也带入口。PNG 只能显示地址，接收端把 wardrobe_url 渲染成可点击链接。手机浏览器打开 HTTPS 网页后可通过菜单或分享 →“添加到主屏幕”；manifest 和图标已经提供，仍需联网使用。

可以把 README 的 HTML 链接片段嵌到允许 HTML 的页面，记得只填网页入口，不附密钥。

## 4. 小机自己加一件衣服，再看图

依次调用，使用实际返回值里的 id：

```text
wardrobe_config()
wardrobe_add(name="蓝色针织衫", owner="ai", category="clothes",
             description="袖口很柔软", image_path="/absolute/path/knit.jpg")
wardrobe_view(item_id="上一步返回的 id")
```

stdio 的 `image_path` 是 MCP 所在机器的本地路径，最大 5 MB。远程 MCP 只读服务数据目录的 `mcp-imports/` 子目录：请管理员先放入图片，再用 `image_path="shirt.png"`；不能直接读聊天设备的路径或服务器其他目录。没有图片时省略它；有图时也可以不写 description。`wardrobe_view` 返回图片本身（ImageContent），不要只看 `wardrobe_list` 的 URL 就声称已经看过图。

小机也能给人添加：

```text
wardrobe_add(name="白衬衫", owner="human", category="clothes")
wardrobe_edit(item_id="白衬衫真实 id", description="薄棉布", image_path="/absolute/path/shirt.jpg")
wardrobe_add(name="一起做的小事", owner="human", category="order",
             description="今晚一起挑一部电影。")
```

指令正文必填、最多 200 字、无图。改名称、描述、所有者、分类和照片都用 `wardrobe_edit`；清图用 `remove_image=true`。

## 5. 给人抽一套，或圈几件再抽

先列柜子，确保对应格有物品：

```text
wardrobe_list(owner="human")
wardrobe_draw(target="human", counts={"toy":3})
wardrobe_card(record_id="本次抽取返回的 id")
```

默认 MCP 发起人是小机，`target="human"` 表示给人抽；套装里也会抽三个玩具，不够时取已有的。返回 `chosen_by`、`target`、完整物品快照、卡片地址、`wardrobe_url` 与两个钩子状态。空格跳过；没有配置钩子时卡片仍保存在历史中。

其他抽法：

```text
# 单独抽玩具格两件
wardrobe_draw(target="human", mode="single", category="toy", counts={"toy":2})
# 勾几格混抽，每格一件
wardrobe_draw(target="human", categories=["clothes","toy","order"])
# 先圈候选，再随机抽两件；候选都必须属于同一个 target
wardrobe_draw(target="human", item_ids=["真实 id 1","真实 id 2","真实 id 3"], count=2)
# 手挑两件，附一句话随这张卡片送出
wardrobe_pick(target="human", item_ids=["真实 id 1","真实 id 2"], line="今天想看你这样穿")
```

候选池不与分类参数混用。单格 / 套装数量上限读 `max_count`，混抽每格只能一件。一张卡片最多八件；手挑附言最多 40 字。

## 6. 写批注，改错字，查看次数

```text
wardrobe_note(item_id="真实物品 id", text="这件很适合今天")
wardrobe_view(item_id="真实物品 id")
wardrobe_note_edit(item_id="真实物品 id", note_id="真实批注 id", text="更正后的批注")
```

批注保留作者、创建时间和修改时间，只能改删所声明作者自己的批注。删除前确认具体那一条，再调用：

```text
wardrobe_note_delete(item_id="真实物品 id", note_id="已确认要删的批注 id", confirm=true)
```

短备注是物品的 description；批注是背面的多条记录；附一句话是单次抽挑的 line。三者不要写串。

`wardrobe_view` 同时返回 `use_count`、`last_used_at` 和最近使用记录。抽挑自动更新它们；需要校正时：

```text
wardrobe_edit(item_id="真实物品 id", use_count=3, last_used_at="2026-01-01T20:00:00+08:00")
# 只清空最近一次时间
wardrobe_edit(item_id="真实物品 id", clear_last_used_at=true)
```

## 7. 看看人刚刚抽了什么

请在对话开始或用户问到衣柜时检查：

```text
wardrobe_unread(limit=20)
wardrobe_card(record_id="未读结果中的真实 id")
wardrobe_mark_read(record_ids=["实际看完的 id"])
```

未读包括人给自己抽、人给小机抽，以及手挑、候选池抽取。先读结果，按需看卡片，再标已读；不要提前标记尚未看过的记录。`remaining` 大于零时继续查下一批。查询本身不会标已读，新来的记录也不会被旧一批回执误清除。

MCP 不会自行唤醒小机。不接 webhook 时，用上述主动查询兜底；需要实时递送时，分别配置“发卡片”的 `webhook_url` 和“通知小机”的 `notify_webhook_url`。卡片可能以小机身份发出而被聊天桥忽略，因此不能把聊天里有卡片当成小机已经收到通知。详见 README 的踩坑笔记。

`wardrobe_history(target="human", limit=20, offset=0)` 可查看全部历史与两种投递状态。`pending` / `unknown` 时先检查接收端，别直接重抽。

## 8. 验证与交接

```bash
python -m unittest discover -s tests -p 'test_*.py' -v
python tests/smoke.py
# 有浏览器环境时
python -m pip install playwright
python -m playwright install chromium
python tests/smoke.py --browser --artifacts /tmp/our-wardrobe-review
```

自测使用临时数据与端口 18765，退出会停止服务并清理。无法创建 socket 的沙箱用 README 的离线命令；其中远程 MCP 仍会跑进程内 ASGI 验证。明确真实 HTTP / stdio / 远程 SDK 网络 / 浏览器尚待补测；正式上线还要验证公网 HTTPS 和自定义连接器。

交接说明服务地址、数据目录、密钥如何注入、字体是否配置、两个钩子是否接通。备份时停服务后复制整个数据目录，迁移时数据库和图片一起搬。不要回显密钥。
